**Owner asked for both of these next (design agreed, not built):**
A. **End meeting fix (bug).** The agenda clock starts on the first transcript line and only a scripted replay ever ends it (`server/src/host/meeting.ts`, `endMeeting`), so a live meeting keeps counting and heartbeating after the visitor leaves, and the next visitor inherits the old clock, questions and tasks. Plan: (1) new `END_MEETING` command, screen-only (`shared/src/commands.ts`, handled in the server; the meeting module needs a way to receive it, `hub.onCommand` currently takes one handler, `app.ts:266`); it freezes the clock and stops the heartbeat; (2) the next transcript line after an end starts a fresh meeting (clock reset, notetaker questions and tasks cleared, opening re-published); (3) the NPC process sends it when the last human leaves (`npc/runner.ts` `ParticipantDisconnected`; it already holds a `?role=screen` socket in `npc/main.ts`); (4) an "End meeting" button on `/screen`. Workaround until built: `bash scripts/live-down.sh` then `live-up.sh` between visitors.
B. **Host mode (a person plays the host).** Needs: Sam's seat playable, with the AI Sam stepping aside when a person takes it (`npcs[].playable`, `npc/runner.ts` cast logic); host controls in the `/demo` Kaki Host tab shown only to the host (dispatch/dismiss, next agenda item, end meeting; commands are screen-only today, so decide how a host on `/demo` is allowed to send them, e.g. signed-in host or login off); Sam's spoken cues (opening, time-out, dispatch, closing) shown to a human host as suggestions instead of spoken; a host briefing card (goal and the decision to land); and the AI attendees' prompt changed so they take their lead from the person hosting (`npc/director.ts` host rules). View: for the booth keep the visitor a participant (Wingman shows best); host mode is a second mode, "Run the meeting, with Kaki coaching you".

## Ranked

1. **Run the whole live path once, timed (test).** Visitor speaks -> AI attendees answer -> notetaker finds a task -> Sam announces it -> the phone accepts -> Wingman drafts -> Kaki runs. Pieces are proven separately; Azure, the real model, real acoustics and the spoken cues are "not verified live" (HANDOFF). Needs the owner (clicks, microphone, keys).
2. **A task for a role an AI plays has nobody to accept it (gap, small).** Open in the status note. Most roles at the booth are AI. Pick a rule (for example Sam keeps them on the screen and says so) and test it.
3. **Voice latency and mishearing (test).** About 950 ms pipeline overhead before model and Azure. The smoke test saw "the build crashes after ten customers" recognised as "belt crashes off to 10 customers". Measure time to first spoken word with the real model; try messy and accented sentences.
4. **Re-run earlier failures marked fixed (test, cheap).** Company search throwing on missing `date`/`source` (smoke rows 6, 7); Gitea draft inventing a bug template; launch-date task on the wrong role; open questions showing 0; the "Email a streamer" run marked FAIL in `final-actions-results.md`. Compare against the saved events.
5. **Deployment safety.** LiveKit runs with `--dev` public keys; Azure VM LiveKit ports are closed until a production config exists. Blocks visitors on their own devices; not needed for one laptop at the booth.
6. **Smaller:** round-16 duplicate-question drop in the notetaker; wire the visitor-probe replay into the eval (`REPLAY` folder choice, `answeredQuestions` check); calendar grid and sending animation (FAIL in the recheck); unmerged branches `feature/mock-crm-nocodb` and `feature/contextual-timestamps`; the shared-file PR.
